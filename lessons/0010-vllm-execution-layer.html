一张图的三种录法

nano-vllm 的 capture_cudagraph 只能录 decode。vLLM 把「录图」做成了三种模式，还能一边编译一边录——这一课讲清 CUDAGraphMode 到底在权衡什么。

1Executor：谁来跑这一批

Executor部署形态典型场景
UniProcExecutor单进程单卡本地调试、小模型
MultiprocExecutor本机多进程单机 TP / PP
RayExecutorV2跨机、Ray 集群多机、弹性伸缩

三者对上层暴露同一个接口：execute_model(scheduler_output) 和 sample_tokens()。调度器完全不知道底下有多少张卡——这是 vLLM 能把「单卡」和「千卡」用同一份调度代码跑起来的原因。

execute_model(scheduler_output)
  ├─ 把 num_scheduled_tokens 展开成每个 token 的位置
  ├─ 更新 block table / slot mapping（和 nano-vllm 一模一样）
  ├─ 选 attention backend，跑前向

Attention backend 为什么要插件化

vllm/v1/attention/backends/ 下有 flash_attn、flashinfer、triton、flex_attention、composite、cpu_attn 等十余个实现。原因：

  • 硬件差异：Hopper / Blackwell 的新特性只有特定 kernel 支持；CPU 和 Ascend 需要完全不同的实现。
  • 长度差异：短序列用简单 kernel 就够，长序列需要分块 + 在线 softmax。
  • mask 差异：causal、sliding window、双向（encoder）、自定义 mask，实现策略不同。

后端在启动时根据「模型 + 硬件 + 配置」自动选取，接口统一。你在 nano-vllm 里看到的 flash_attn_varlen_func / flash_attn_with_kvcache 两种调用，就是 FlashAttention backend 内部的两种路径。

3CUDA Graph 的三种模式

vllm/config/compilation.py · L130–140class CUDAGraphMode(enum.Enum):
    NONE = 0
    PIECEWISE = 1
    FULL = 2
    FULL_DECODE_ONLY = (FULL, NONE)
    FULL_AND_PIECEWISE = (FULL, PIECEWISE)

最后两个是「组合模式」，元组的第一位用于 decode 批次，第二位用于 mixed 批次（即含 prefill 的批次）[compilation.py L142–152]。

模式怎么录适用
NONE不录，纯 eager调试、不支持的算子
PIECEWISE把模型切成若干「静态片段」，每段各录一张图；attention 等动态算子留在图外prefill / mixed 批次
FULL完整model forward作为图单位backend支持的decode或prefill/mixed桶
FULL_DECODE_ONLYdecode 用 FULL，mixed 用 NONE保守配置
FULL_AND_PIECEWISEdecode 用 FULL，mixed 用 PIECEWISE一种混合策略，收益需测量

为什么 prefill 也能录图（nano-vllm 做不到）

nano-vllm 的 prefill 每轮 shape 都变（token 总数不定），所以只能 eager。vLLM 的办法是 分段：

[embedding] [norm] [qkv] [attention ✗ 动态] [o_proj] [mlp] [norm]
   └────── 录成图 ──────┘        └─── eager ───┘  └── 录成图 ──┘

把 attention 切成图与图之间的「洞」，其余静态部分照录。这样即使总 token 数不同，每个片段的 shape 也可以是固定的（按 token 数分桶）。这就是 piecewise 的核心思想。

一句话区分

FULL捕获完整model forward；backend支持时也可以处理non-uniform prefill/mixed。PIECEWISE切分模型，动态部分可留在图外。二者都需遵守捕获形状和地址合约，通常结合分桶与padding。

4核对模型、logits与采样的真实边界

nano-vllm capture只包含self.model，compute_logits在图外。此vLLM提交的常见GPUModelRunner路径同样在_model_forward返回后选取sample_hidden_states，再compute_logits。因此不能依据FULL名字断言logits一定入图；见实际forward边界。

nano-vllm将输入值拷入预分配graph缓冲；vLLM还通过attention metadata、backend能力与模式调度协调更多模型/设备路径。应逐个核对缓冲字段，而非依据张量个数推断性能。

缩写切什么通信vLLM 里的位置

注意 vLLM 的 DP 是在 EngineCore 进程级做的：每个 DP rank 有自己的调度器和 worker 组，前端把请求分发过去。nano-vllm 完全没有这一层——它只有 TP。

6练习 A · 给场景选模式

下面三个场景，你会选哪种 CUDAGraphMode？

  1. 线上服务的 decode 占 90% 时间，prefill 偶尔来一条长 prompt。
  2. 你在调试一个自定义 attention 算子，需要能断点、打印中间张量。
  3. 离线批量打分（只用 prefill，不做生成）。
展开：参考答案

① FULL_AND_PIECEWISE可作为候选配置，随后在固定负载上与其他支持模式对照；不能预先保证收益最大。

② NONE：图内无法断点，调试必须退回 eager。

③ 先查backend的FULL能力和本轮shape桶：支持时prefill也可FULL，否则评估PIECEWISE或NONE。用固定负载测量后选择。
